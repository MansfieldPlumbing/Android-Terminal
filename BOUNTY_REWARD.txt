Yes — I do have the current docs from the repository snapshot, and you were right to worry about them. The code is already moving faster than the prose.

The README still defines Terminal around an in-process PowerShell runspace, calls the VT layer TerminalEngine, calls the extension mechanism “hardpoints,” and calls release payloads “cargo.” docs/ARCHITECTURE.md repeats TerminalEngine, hardpoints, cargo, and even preserves a sentence explaining that ADB has “no VOM” dependency. docs/BOS-ORGANIZATION.md is particularly stale: it is full of router, cargo, admission, cargo host, etc. And BOS_SPEC.md literally contains “Subsystem eventually grows as detachable capability moss.” That sentence needs to die with fire.

I suggest we maintain this as an append-only terminology ledger. I won't renumber or silently remove entries; once something is cleaned up, we mark it RESOLVED.

ISM-001 — Subsystem as Terminal identity. Replace live namespace Subsystem, using Subsystem, ADB identities/log tags/cert names, and any docs treating Subsystem as a Terminal component. Likely code namespace: Terminal.Android.Adb. Historical statements about a retired Subsystem donor are different: either quarantine them in archaeology/donor documentation or retain them explicitly as history; do not mechanically pretend the donor was named Terminal. Current BOS prose treating Subsystem as future architecture is simply wrong.
ISM-002 — VOM / runtime-broker ontology. Remove from current Terminal documentation, including negative assertions like “has no VOM dependency.” Terminal doesn't need to carry an obituary for an architecture it doesn't have. The current docs contain exactly this stale assertion.
ISM-003 — Terminal.Engine / TerminalEngine. Replace Terminal-owned generic “engine” identity with the actual Terminal.VT vocabulary. The folder is already Terminal.VT; project namespace, references, tests, docs and class identity are lagging behind. README and platform-boundary docs still teach Terminal.Engine as canonical.
ISM-004 — Router / Terminal.Router. Replace with Multiplexer throughout project, namespace, assembly, protocol names, native symbols, docs, tests and status reporting. Terminal.Multiplexer is already the folder while its internals are still Terminal.Router.
ISM-005 — RouterCodec. Kill specifically. It is just four protocol constants under a grandiose name. Fold it into MultiplexerProtocol or otherwise name the actual wire-format responsibility.
ISM-006 — Route when the thing is actually an interactive session. Audit RouterRoute, RouteId, ConsoleRouteStatus, _routes, etc. Do not blind-replace legitimate protocol routing terminology, but if the object represents one PTY/ConPTY-backed interactive session, call it Session. Current IPtySession is already the semantic confession.
ISM-007 — cargo. Replace with the boring noun that actually applies: application, process, executable, package, module, assembly, shared library, worker. The docs use “cargo” for everything from PWSH to .so files to Kestrel.
ISM-008 — hardpoint. Audit and replace with the actual category: application, package, UI contribution, settings contribution, etc. The docs currently make “hardpoint” part of the repository ontology, schema names, release system, Edit, Surface and PowerShell architecture. This is one of the biggest terminology migrations.
ISM-009 — admission / admitted everywhere. Replace with the actual operation: authorize, allow, register, install, load, start, create, accept. Keep the concept only where there is genuinely a security/policy decision deserving a distinct authorization term. BOS policy/admission appearing everywhere is abstraction fog. BOS> TORCH ON does not need an academic admissions office.
ISM-010 — NativePwshConsole. Replace product/root namespaces, component identities, service names and strings with Terminal-owned identities. It survives as the Android root namespace and throughout the source.
ISM-011 — PTY as the cross-platform abstraction. Generic layer becomes PseudoConsole. Windows implementation = ConPTY / CreatePseudoConsole; Android implementation = PTY / forkpty. Thus audit IPtySession, PtySessionFactory, WindowsPtySession, AndroidPtySession. The OS-specific implementation may truthfully retain PTY.
ISM-012 — Terminal-owned IWhatever interfaces. Drop the C# I prefix for interfaces we own when an interface is actually justified at all. Do not rename framework-owned IDisposable, Android listener interfaces, etc. IPtySession, IAdbTransport, and ISurfaceResourceResolver are current candidates.
ISM-013 — Console/Terminal conflation. Audit Terminal-owned names such as NativeConsoleView, ConsoleRouterStatus, ConsoleRouteStatus, and ConsoleBackend. Console = process-facing attachment; Terminal = VT interpretation/presentation. NativeConsoleView is painting terminal cells, so its name is particularly suspect. Current BOS status objects still say ConsoleRouterStatus.
ISM-014 — BOS casing drift. BOS-owned source/type/command identity must follow the uppercase rule. Current tree has Terminal.BOS beside Terminal.Bos.csproj, BosEngine, BosStatus, etc. Normalize deliberately, not opportunistically.
ISM-015 — wrong BOS prompt. Canonical prompt is BOS:\>. Current canonical docs repeatedly show BOS> and therefore teach the wrong product syntax. For example BOS_SPEC.md currently shows BOS> TORCH ON and BOS> START CAMERA.
ISM-016 — PowerShell-first product architecture. This is more serious than naming. README currently opens with Terminal directly hosting PowerShell inside Android and describes a persistent in-process runspace as the product baseline. That conflicts with the architecture we're establishing: BOS is the resident command environment; PWSH/CoreCLR is optional subordinate execution. Docs must stop teaching the old topology.
ISM-017 — PowerShell filesystem as Terminal's primary filesystem identity. Home:\profile.ps1, app-private PowerShell home, etc. can remain as PowerShell projection, but BOS documentation must lead with the BOS filesystem/prompt rather than make the PowerShell PSDrive look like the machine's native namespace. README currently does exactly that.
ISM-018 — metaphorical architecture prose. Kill prose such as “capability moss,” “semantic trunk,” “cargo,” “granite seam,” and similar invented topology where ordinary systems nouns work. The Subsystem ... detachable capability moss sentence is the poster child.
ISM-019 — generic Host where nothing is actually being hosted. This is conditional, not a global ban. PSHost / PowerShell host is a real Microsoft term and stays. “Native cargo host” should disappear with cargo; other *Host types should be checked against what they genuinely own.
ISM-020 — C# visual casing inconsistency. _camelCase, camelCase, PascalCase, BOS ALL-CAPS, native snake_case are currently mixed for partly legitimate language reasons and partly history. Do not mass-rewrite this yet. We need one explicit house-style decision for Terminal-owned C#, while BOS remains its stricter ALL-CAPS island. This is the _exitCode problem you spotted.
